# MoonVCR 任务拆解

状态：阶段 3（任务草案，待设计确认）

原则：先做能被 GitHub 检查、能在无网络环境运行的垂直闭环；每项任务都必须带测试或可复现证据。任务完成后形成真实功能提交，不预先制造提交次数。

## P0：必须完成

### T01 项目骨架与合规基线

- 产出：MoonBit 模块骨架、许可证、基础 README、CI 最小配置、最小测试。
- 验收：本地可执行检查/测试；仓库中明确 MoonBit 为主语言和项目边界。
- 提交边界：项目初始化功能提交。

### T02 请求/响应/交互模型

- 产出：`Request`、`Response`、`Header`、`Body`、`Interaction`、错误类型。
- 验收：构造成功/错误值的测试通过；不依赖文件或网络。
- 提交边界：模型与错误类型功能提交。

### T03 cassette schema 与确定性 JSON codec

- 产出：版本化 schema、编码/解码、未知版本错误、稳定字段/数组排序。
- 验收：fixture 往返后字节级稳定；非法输入返回可定位错误。
- 提交边界：codec 功能提交。

### T04 URL、查询参数和请求头规范化

- 产出：纯函数规范化器与配置项。
- 验收：大小写、查询参数顺序和可忽略头的测试明确通过/不通过行为。
- 提交边界：规范化功能提交。

### T05 可组合匹配器

- 产出：方法、URL、查询参数、头、body 策略和候选选择。
- 验收：命中、未命中、候选差异、顺序消费测试通过。
- 提交边界：matcher 功能提交。

### T06 record/replay 会话引擎

- 产出：`record`、`replay`、严格离线模式与显式 transport 接口。
- 验收：replay 命中不调用 transport；未命中返回类型化错误且不触网；record 能写入并立即回放。
- 提交边界：会话引擎功能提交。

### T07 默认敏感信息清理

- 产出：敏感头、查询参数和调用方 JSON 路径清理策略。
- 验收：脱敏 fixture 不含真实值；清理失败阻止落盘。
- 提交边界：redact 功能提交。

### T08 结构化 mismatch 诊断

- 产出：字段级差异类型、稳定摘要、候选索引信息。
- 验收：至少覆盖 method、URL/query、header、body、sequence 差异；摘要不泄露敏感值。
- 提交边界：诊断功能提交。

### T09 transport adapter 与可运行示例

- 产出：一个已验证的 adapter、无网络 replay 示例、显式 record 示例。
- 验收：在关闭网络时 replay 示例仍通过；README 能让新用户复现。
- 提交边界：adapter 与示例功能提交。

### T10 核心测试矩阵与 CI 完整化

- 产出：codec、matcher、redact、session、diagnostics 的测试矩阵；CI 执行格式检查、检查、构建和测试。
- 验收：CI 从干净环境通过；失败输出可定位。
- 提交边界：测试与 CI 功能提交。

### T11 README、发布元数据与 Mooncakes 检查

- 产出：安装、API、录制/回放、限制、安全、许可证、来源说明、版本元数据和发布检查清单。
- 验收：按 README 在无网络条件完成 replay；包元数据通过发布前检查；仓库链接可公开访问。
- 提交边界：文档与发布功能提交。

## P1：截止日前有余力再做

- JSON 响应字段的更细粒度结构化 matcher。
- cassette 分片或只读共享 fixture。
- 更丰富的 body 编码和大响应存储策略。
- 一个实际 MoonBit HTTP 客户端的完整 adapter（前提是 API 稳定且不影响 P0）。

## 明确延期

- TLS MITM 和系统代理。
- 浏览器录制器。
- 分布式 cassette 服务。
- 动态模板、随机数据生成和完整 JSONPath 语言。
- 多语言 SDK 或机械移植其他 VCR 实现。

## 真实提交节奏

T01 至 T11 预计形成至少 11 个有意义的提交，但实际以功能完成度为准。任何提交都必须包含源代码、测试、文档或可验证配置的实质变化；不得使用空提交、无意义拆分、重复提交或事后改写历史。

## 里程碑门禁

### M1：可保存的数据

完成 T01-T03，能够创建、编码、解码和稳定重写 cassette。

### M2：可匹配的请求

完成 T04-T05，能够在内存中确定性地找到交互并解释未命中原因。

### M3：可离线运行的闭环

完成 T06-T09，能够录制、脱敏、回放和运行无网络示例。

### M4：可提交的仓库

完成 T10-T11，CI、README、许可证、Mooncakes 元数据和 Git 历史达到赛事验收条件。

申报书放在 M3 之后编写，内容只描述仓库中已经存在且可运行的功能，不提前承诺未实现能力。
