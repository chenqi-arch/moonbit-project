# MoonVCR 任务拆解

状态：阶段 4（T01-T11 已完成）

原则：先做能被 GitHub 检查、能在无网络环境运行的垂直闭环；每项任务都必须带测试或可复现证据。任务完成后形成真实功能提交，不预先制造提交次数。

## P0：必须完成

### T01 项目骨架与合规基线

- 产出：MoonBit 模块骨架、许可证、基础 README、CI 最小配置、最小测试。
- 验收：本地可执行检查/测试；仓库中明确 MoonBit 为主语言和项目边界。
- 提交边界：项目初始化功能提交。

### T02 请求/响应/交互模型

- 产出：`Request`、`Response`、`Header`、`Body`、`Interaction`、错误类型。
- 验收：构造成功/错误值的测试通过；不依赖文件或网络。
- 提交边界：模型与错误类型功能提交。

### T03 cassette schema 与确定性 JSON codec

- 产出：版本化 schema、编码/解码、未知版本错误、稳定字段/数组排序。
- 验收：fixture 往返后字节级稳定；非法输入返回可定位错误。
- 提交边界：codec 功能提交。

### T04 URL、查询参数和请求头规范化

状态：已完成（提交 `7571d46`）

- 产出：纯函数规范化器与配置项。
- 验收：大小写、查询参数顺序和可忽略头的测试明确通过/不通过行为。
- 提交边界：规范化功能提交。

### T05 可组合匹配器

状态：已完成（提交 `cec63b8`）

- 产出：方法、URL、查询参数、头、body 策略和候选选择。
- 验收：命中、未命中、候选差异、顺序消费测试通过。
- 提交边界：matcher 功能提交。

### T06 record/replay 会话引擎

状态：已完成（提交 `317611b`）

- 产出：`record`、`replay`、严格离线模式与显式 transport 接口。
- 验收：replay 命中不调用 transport；未命中返回类型化错误且不触网；record 能写入并立即回放。
- 提交边界：会话引擎功能提交。

### T07 默认敏感信息清理

## P1：截止日前有余力再做

- JSON 响应字段的更细粒度结构化 matcher。
- cassette 分片或只读共享 fixture。
- 更丰富的 body 编码和大响应存储策略。
- 一个实际 MoonBit HTTP 客户端的完整 adapter（前提是 API 稳定且不影响 P0）。

## 明确延期

- TLS MITM 和系统代理。
- 浏览器录制器。
- 分布式 cassette 服务。
- 动态模板、随机数据生成和完整 JSONPath 语言。
- 多语言 SDK 或机械移植其他 VCR 实现。
